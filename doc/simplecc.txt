INTRODUCTION                                                     *simplecc*

SimpleCC is a Vim 9 Language Server Protocol client.  A Rust daemon manages
language-server processes and JSON-RPC traffic while Vim9 script provides the
editor UI.

Features include completion, hover, diagnostics, navigation, rename,
formatting, code actions, symbols, hierarchy views, inlay hints, semantic
tokens, code lenses, snippets, and Julia environment support.

Requirements:

- Vim 9.0 or newer with +vim9script, +job, +channel, +popupwin, +timers, and
  +textprop.
- A daemon built by install.sh or selected with |g:simplecc_daemon_path|.
- A configured language server on PATH or installed with |:SimpleCCInstall|.

==============================================================================
INSTALLATION                                         *simplecc-installation*

vim-plug example: >

  Plug 'beamiter/simplecc', { 'do': './install.sh' }
<
Manual build from the plugin root: >

  ./install.sh
<
The installer runs a locked release build and atomically installs the verified
daemon as lib/simplecc-daemon.  The plugin directory must be on 'runtimepath'.

To use another daemon executable: >

  let g:simplecc_daemon_path = '/absolute/path/to/simplecc-daemon'
<
Generate help tags manually if your plugin manager does not do so: >

  :helptags /path/to/simplecc/doc
<
==============================================================================
QUICK START                                             *simplecc-quick-start*

1. Install the plugin and daemon.
2. Install a language server, for example: >

     :SimpleCCInstall rust-analyzer
<
3. Open a supported file.  SimpleCC starts automatically by default.
4. Check status with |:SimpleCC|.
5. Use 'gd' for definition, 'K' for hover, and '<Leader>rn' for rename.

SimpleCC first looks for a managed server and then searches PATH.  A
system-installed language server needs no additional setup.

CONFIGURATION                                         *simplecc-configuration*

Set an explicit JSON configuration before SimpleCC is loaded: >

  let g:simplecc_config_path = expand('~/.config/simplecc/simplecc.json')
<
Without this option, configuration is selected in order:

1. simplecc.json in the detected project root
2. .simplecc.json in the detected project root
3. ~/.config/simplecc/simplecc.json
4. built-in defaults

Example: >

  {
    "languageServers": {
      "rust-analyzer": {
        "command": "rust-analyzer",
        "args": [],
        "filetypes": ["rust"],
        "rootPatterns": ["Cargo.toml"],
        "priority": 100,
        "initializationOptions": {},
        "settings": {}
      }
    }
  }
<
Entry fields:

command                 Executable name or absolute path.
args                    Command-line arguments.
filetypes               Vim filetypes handled by the server.
rootPatterns            Project marker filenames.
priority                Optional integer server priority.  Higher values win;
                        ties are ordered by server name.
initializationOptions   Value sent during LSP initialization.
settings                workspace/configuration values and live settings.

Use |:SimpleCCConfig| to open or create a project configuration and
|:SimpleCCReloadConfig| to validate it and hot-push settings to running
servers.  Changes to command, args, filetypes, rootPatterns, priority, or
initializationOptions require |:SimpleCCRestart|.  Invalid JSON is reported
without replacing the running configuration.

See simplecc.json.example in the repository for complete examples.

*:SimpleCCPullDiag*              Request pull diagnostics.
*:SimpleCCJuliaActivate* [dir]   Activate a Julia environment.

MAPPINGS                                                   *simplecc-mappings*

Default Normal-mode mappings:

gd              Definition
gr              References
K               Hover
gi              Implementation
gy              Type definition
<Leader>rn      Rename
<Leader>ca      Code action
<Leader>fm      Format
<Leader>o       Document outline
<Leader>ih      Toggle inlay hints
[d / ]d        Previous / next diagnostic

Default Visual-mode mappings:

<Leader>ca      Code action over the selection
<Leader>fm      Format the selection

Over a selection, |:SimpleCCAction| sends the real range and the diagnostics
that intersect it, which is what makes "extract function", "extract variable",
"move to a new file" and diagnostic-bound quickfix actions available at all;
|:SimpleCCFormat| uses textDocument/rangeFormatting and formats only those
lines. Without a range both behave exactly as before.

Optional mapping targets:

  <Plug>(simplecc-show-diagnostic)   |:SimpleCCDiag|
  <Plug>(simplecc-selection-expand)  |:SimpleCCSelExpand|  (Normal and Visual)
  <Plug>(simplecc-selection-shrink)  |:SimpleCCSelShrink|  (Normal and Visual)
  <Plug>(simplecc-code-action)       |:SimpleCCAction|     (Normal and Visual)
  <Plug>(simplecc-format)            |:SimpleCCFormat|     (Normal and Visual)

Insert-mode Tab, Shift-Tab, Up, Down, and Enter navigate or accept completion.
Tab is context-aware and acts on the first of these that applies: advance the
completion menu, jump to the next snippet placeholder, request completion when
the cursor follows a word, or insert a literal tab. Shift-Tab moves backward the
same way. Because the menu takes priority, a popup that appears while editing a
snippet placeholder is still selectable with Tab. An active snippet finishes
automatically once the cursor leaves its line or moves before its start, so Tab
returns to ordinary completion.

Disable all defaults before loading the plugin: >

  let g:simplecc_no_default_maps = 1
<
                                                     *simplecc-native-options*
Vim's own extension points ~

In every buffer the daemon serves, SimpleCC also points three Vim options at
the language server, so the keys that work everywhere else in Vim keep working
here:

  'omnifunc'      CTRL-X CTRL-O completes from the server.
  'tagfunc'       CTRL-], :tag and CTRL-W } jump to the definition and push
                  the tag stack, so CTRL-T comes back.
  'formatexpr'    gq and gw format through textDocument/rangeFormatting.

Each of them falls back to what Vim would have done on its own — keyword
completion, the tags file, internal formatting — whenever it cannot do better:
the daemon is not running, the buffer has no server, the server never
advertised the capability, or 'tagfunc' was asked for something that is not
the identifier under the cursor. Auto-formatting while typing ('formatoptions'
"a" and "t") is always Vim's, never a round-trip.

|g:simplecc_native_options| controls whether the options are set at all, and
whether a value the buffer already has is replaced.

OPTIONS                                                     *simplecc-options*

All options must be set before plugin/simplecc.vim is loaded.

                                                *g:simplecc_auto_start*
g:simplecc_auto_start            number  default: 1
        Start SimpleCC on VimEnter.

                                        *g:simplecc_no_default_maps*
g:simplecc_no_default_maps       number  default: 0
        Disable all default mappings.

                                               *g:simplecc_config_path*
g:simplecc_config_path           string  default: ''
        Explicit simplecc.json path.

                                               *g:simplecc_daemon_path*
g:simplecc_daemon_path           string  default: ''
        Explicit daemon executable.

                                             *g:simplecc_auto_restart*
g:simplecc_auto_restart          number  default: 1
        Restart a daemon that exited unexpectedly, with exponential backoff
        (see |simplecc-daemon|). Set to 0 to leave a crashed daemon down;
        |:SimpleCCRestart| then remains the only way back.

                                             *g:simplecc_max_restarts*
g:simplecc_max_restarts          number  default: 5
        Crashes within one minute before the supervisor gives up, reports it
        once, and stops respawning. |:SimpleCCRestart| clears the breaker.

                                          *g:simplecc_request_timeout*
g:simplecc_request_timeout       number  default: 30000
        Milliseconds before a request that carries a reply callback is
        answered with an error instead of waiting on a daemon that has
        wedged. Set to 0 to wait forever.

                                          *g:simplecc_native_options*
g:simplecc_native_options        number  default: 1
        Point Vim's own extension points at the language server in buffers the
        daemon serves — see |simplecc-native-options|.
            0   never; 'omnifunc', 'tagfunc' and 'formatexpr' are left alone.
            1   set each one only where the buffer has no value of its own, so
                a filetype plugin that configured 'omnifunc' keeps it.
            2   always, replacing whatever the filetype plugin chose.

                                         *g:simplecc_tagfunc_timeout*
g:simplecc_tagfunc_timeout       number  default: 1000
        Milliseconds 'tagfunc' waits for the server. CTRL-] has to be answered
        with a list, so this is the only place SimpleCC waits on the daemon;
        running out of time falls back to the tags file rather than failing.

                                     *g:simplecc_resource_operations*
g:simplecc_resource_operations   number  default: 1
        Apply the create / rename / delete steps of a workspace edit, not only
        its text edits. This is what makes a rename-file refactor work:
        rust-analyzer's "move to submodule", TypeScript's "move to a new
        file", and every "rename symbol" that also renames the file it lives
        in send the file move and the edits to its importers as one edit.
        The steps are applied in the order the server sent them, and the first
        one that fails stops the rest — a half-applied refactor is worse than
        none.
        A file that already exists is never truncated or replaced unless the
        server explicitly asks to overwrite it. Buffers follow the files: a
        renamed buffer is reopened under its new name, a deleted one is wiped.
        Set to 0 to accept only the text half; the server is then told the
        whole edit was rejected rather than being left to believe the files
        moved.

                                             *g:simplecc_auto_complete*
g:simplecc_auto_complete         number  default: 1
        Enable automatic completion.

                                              *g:simplecc_change_delay*
g:simplecc_change_delay          number  default: 120
        Document-change debounce in milliseconds.

                                            *g:simplecc_complete_delay*
g:simplecc_complete_delay        number  default: 80
        Completion debounce in milliseconds.

                                  *g:simplecc_complete_min_chars*
g:simplecc_complete_min_chars    number  default: 1
        Minimum typed characters before automatic completion.

                                  *g:simplecc_complete_max_items*
g:simplecc_complete_max_items    number  default: 100
        Maximum completion items.

                              *g:simplecc_complete_resolve_delay*
g:simplecc_complete_resolve_delay number default: 120
        Completion-item resolve debounce in milliseconds.

                                      *g:simplecc_complete_sort*
g:simplecc_complete_sort         number  default: 1
        Honour the ranking hints the language server sends with each
        completion item:
                - "sortText" decides the menu order. The daemon applies it
                  before cutting the list down to
                  |g:simplecc_complete_max_items|, so the candidates that
                  survive the cut are the relevant ones. Items sharing a
                  sortText keep the server's own order; an item without one
                  sorts by its label.
                - "filterText" is the text the server wants matched against
                  what you typed. When it differs from the text that would
                  be inserted (postfix completions, attribute completions),
                  the item is marked "equal" so Vim's own prefix filter
                  does not drop it. Requires patch-9.0.1051; on an older
                  Vim the item is offered without the mark.
                - "preselect" moves the server's own answer to the top of
                  the menu and drops "noselect" for that menu, so <CR>
                  accepts it directly.
        Set to 0 to take the items in the order the server happened to send
        them and filter them with Vim's rules alone.

                              *g:simplecc_complete_buffer_words*
g:simplecc_complete_buffer_words number default: 1
        Supplement language-server completion with keyword matches drawn
        from open buffers. Nearby identifiers in the current file are
        offered first, followed by other loaded buffers of the same
        filetype. Words the server already offers are never duplicated.
        These candidates are tagged "buf" in the completion menu and also
        appear before a server is ready or in files with no server. Set to
        0 to rely on the language server alone.

                              *g:simplecc_complete_buffer_max_items*
g:simplecc_complete_buffer_max_items number default: 20
        Maximum number of buffer-word candidates to add to each menu.

                                                *g:simplecc_sign_error*
g:simplecc_sign_error            string  default: 'E>'
                                                *g:simplecc_sign_warn*
g:simplecc_sign_warn             string  default: 'W>'
                                                *g:simplecc_sign_info*
g:simplecc_sign_info             string  default: 'I>'
                                                *g:simplecc_sign_hint*
g:simplecc_sign_hint             string  default: 'H>'

g:simplecc_auto_install          number  default: 0

                                               *g:simplecc_inlay_hints*
g:simplecc_inlay_hints           number  default: 1

TROUBLESHOOTING                                     *simplecc-troubleshooting*

Daemon not found ~

Run install.sh and verify lib/simplecc-daemon is executable, or set
|g:simplecc_daemon_path| to an absolute path.

Server not found ~

Run the server with --version, use |:SimpleCCInstall| where supported, then
run |:SimpleCCRestart|.  Inspect |:SimpleCCLog| for startup errors.

Configuration does not apply ~

Use |:SimpleCCReloadConfig| for settings-only changes.  Use
|:SimpleCCRestart| after changing commands, arguments, initialization,
routing, root patterns, or priorities.  An explicit
|g:simplecc_config_path| takes precedence over discovered files.

No completion or navigation result ~

Check |:SimpleCC|, confirm the current 'filetype' is configured, and inspect
|:SimpleCCLog| for language-server errors.

Julia server does not start ~

Ensure Julia is on PATH, run ':SimpleCCInstall julia-lsp', open a Julia
buffer, and use |:SimpleCCJuliaActivate| in the intended environment.

DAEMON SUPERVISION                                    *simplecc-daemon*

The Rust daemon is managed by simplecore, the supervisor shared by the whole
simple* plugin suite. It is vendored into this repository at
autoload/simplecc/core.vim; that file is generated, do not edit it in place.

What it guarantees:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- A superseded daemon's late exit callback cannot clear the state of the
  replacement that already took its place.
- Output still queued when you stop the daemon is discarded, so an explicit
  stop cannot be undone by an event that was already in flight.
- A daemon that dies is restarted automatically with exponential backoff,
  and the LSP session is rebuilt on the replacement: the workspace is
  re-initialized and every open buffer is re-opened, with no user action.
  If it keeps crashing, the supervisor reports it once and stops trying
  rather than respawning forever; :SimpleCCRestart re-arms it. Turn the
  automatic part off with |g:simplecc_auto_restart|, and set the crash-loop
  threshold with |g:simplecc_max_restarts|.
- Requests are correlated to replies by id and time out after
  |g:simplecc_request_timeout|, so a wedged daemon never leaves a callback
  hanging.

                                                      *:SimpleCCHealth*
:SimpleCCHealth
        Open a full report in a scratch buffer, one "[LEVEL] fact — remedy"
        per line, so it can be read, scrolled and pasted into a bug report.
        Five sections:

        ENVIRONMENT  Vim version, the features each part of the plugin needs
                     (+job, +channel, +timers, +textprop, +popupwin) and
                     'encoding' — LSP columns are UTF-16 over UTF-8.
        BINARY       Where the daemon is, when it was built, and whether it
                     is older than the plugin sources beside it. That last
                     one is the most common failure there is: a plugin
                     manager updates the Vim files and never rebuilds
                     lib/simplecc-daemon, and the only symptom is a feature
                     that quietly does nothing. The remedy is printed with
                     it: run ./install.sh, then |:SimpleCCRestart|.
        CONFIG       Which configuration file is actually in use (the search
                     in |simplecc-configuration|, not a guess), whether it
                     parses, and for each declared server whether its command
                     resolves — on $PATH or in the directory
                     |:SimpleCCInstall| installs into — and which filetypes
                     select it.
        RUNTIME      Daemon state, uptime, crash and restart counts, whether
                     the crash-loop breaker has tripped, in-flight requests,
                     the LSP session, the workspace root, what each running
                     server advertised, and the diagnostics held per server.
        CONTEXT      Why the buffer you ran it from is or is not being
                     served: 'buftype', 'filetype', whether the document was
                     ever opened on the server, whether the server has seen
                     your latest edits, and the values of 'omnifunc',
                     'tagfunc' and 'formatexpr' — see
                     |simplecc-native-options|.

:SimpleCCRestart
        Stop the daemon and start a fresh one. Clears the crash-loop breaker,
        so this is the way back after repeated failures.

:SimpleCCLog
        Open the daemon transcript in a scratch buffer: start and exit events,
        restarts, protocol handshakes, send failures and stderr.

DAEMON COMMAND LINE                                      *simplecc-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it and speaks
JSON over its stdin and stdout.  For diagnosis it also answers: >

  simplecc-daemon --version
  simplecc-daemon --help
  simplecc-daemon --self-test
<
--self-test checks the built-in language-server table resolves, and prints
"ok".
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/.

Every daemon in the simple* suite answers these three the same way.

VENDORED SUPERVISOR                                      *simplecc-simplecore*

The daemon supervisor in autoload/simplecc/core.vim, and the test harness
beside it, are vendored from the suite's shared .simplecore bundle rather
than written here — each plugin carries its own copy so that installing
this plugin alone is enough.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.

The bundle lives at https://github.com/beamiter/simplecore.  To change the
supervisor, clone it beside the plugins, edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<
